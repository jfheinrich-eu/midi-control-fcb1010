## Warning

### W1: Central setup file is not registered by the extension package

- Status: Resolved.
- File: `vscode-uno2-language/package.json:22`
- Issue: The language contribution registers only the `.uno2` extension. `UnO2_Cubase_OBS_Setup.txt` is recognized through the repository-local `.vscode/settings.json` association, but a VSIX installation in another workspace does not provide that filename association.
- Fix: Add a `filenames` entry for `UnO2_Cubase_OBS_Setup.txt` to the language contribution, or document the workspace association as a required installation step.

### W2: Undefined JSDoc type and weak configuration typing

- Status: Ignored by request; no code change applied.
- File: `Behringer_BehringerFCB1010UnO2.js:288-293`
- Issue: `emitStopPulse` references `SurfaceCustomValueVariable`, but that type is not defined in the file. Configuration-facing functions also use generic `object` annotations even though `DriverConfig` is already defined.
- Fix: Define the missing surface-value type and use concrete JSDoc types for `config`, `cloneConfig`, `makeVariantConfig`, `registerDevice`, and related nested configuration objects.

### W3: Non-permitted single-letter callback identifier

- Status: Resolved.
- File: `.github/workflows/pr-bot-review.yml:33`
- Issue: The callback parameter `r` is a single-letter identifier that is not a permitted loop counter under the repository coding rules.
- Fix: Rename it to a descriptive name such as `review`.

### W4: Generated VSIX is not ignored

- Status: Resolved.
- File: `.gitignore:14-15`
- Issue: `make package` creates `vscode-uno2-language/uno2-language-support-0.1.0.vsix`, but `.gitignore` has no `*.vsix` or equivalent generated-artifact rule. The generated package currently appears as an untracked workspace file.
- Fix: Add `*.vsix` or the specific extension output path to `.gitignore`, unless checked-in release artifacts are intentional.

### W5: Extension work is missing from the changelog

- Status: Resolved.
- File: `CHANGELOG.md:7-14`
- Issue: The UnO2 VS Code language extension, VSIX packaging, and syntax-highlighting work are documented in a dated `docs/` entry but are not represented in the project changelog's `Unreleased` section.
- Fix: Add an `Added` or `Changed` entry describing the extension, its installation path, and the validation performed.

### W6: Extension documentation names a different UnO2 manual version

- Status: Resolved.
- File: `vscode-uno2-language/README.md:13`
- Issue: The grammar is described as based on the UnO2 v1.3a manual, while the maintained setup file identifies itself as UnO2 v1.4. The supported syntax/version boundary is therefore unclear.
- Fix: Verify the grammar against the current v1.4 syntax and document the exact supported versions, or explain which v1.4 constructs are intentionally excluded.
